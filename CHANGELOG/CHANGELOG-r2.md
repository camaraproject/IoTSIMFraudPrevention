## iot-sim-fraud-prevention 0.2.0

**iot-sim-fraud-prevention 0.2.0 is an initial public version of this API.**

Changes documented below are compared to version 0.1.0.

- API definition **with inline documentation**:
  - [View it on ReDoc](https://redocly.github.io/redoc/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.2/code/API_definitions/iot-sim-fraud-prevention.yaml&nocors)
  - [View it on Swagger Editor](https://camaraproject.github.io/swagger-ui/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.2/code/API_definitions/iot-sim-fraud-prevention.yaml)
  - OpenAPI [YAML spec file](https://github.com/camaraproject/IoTSIMFraudPrevention/blob/r2.2/code/API_definitions/iot-sim-fraud-prevention.yaml)

### Breaking changes

- `securitySchemes.openId` is now an `openIdConnect` scheme referencing `CAMARA_common.yaml`, instead of an `oauth2` client-credentials flow with a hard-coded token endpoint. Consumers must obtain tokens via their own OpenID Connect discovery document; three-legged access tokens are now supported (#96, PR #101).
- `POST /query` `200` response now always contains both `areaLimit` and `imeiBind`; the `bindImei` property is no longer returned and `imeiBind` contains only `bindStatus` (PR #77).
- `404` now returns the `IDENTIFIER_NOT_FOUND` error code instead of the previous local variant, and `401`/`403`/`404`/`422` responses are served from the Commonalities r4.4 common response definitions (PR #83).
- Local `Bind422`, `Unbind422` and `Query422` response definitions are replaced by the common `DeviceIdentifier422` (PR #83).

### Added

- `device` object in the `200` responses of `POST /bind`, `POST /unbind` and `POST /query`, so the API consumer can disambiguate which device identifier was matched (PR #77).
- `409 INCOMPATIBLE_STATE` response on `POST /bind` and `POST /unbind`, returned when the device is already in the state requested by the operation (PR #77).
- `SERVICE_NOT_APPLICABLE` error code in the `422` response, for identified devices to which this service does not apply (PR #83).

### Changed

- `securitySchemes.openId` changed from `oauth2` client credentials with a fixed token endpoint to `openIdConnect` referencing `CAMARA_common.yaml` (#96, PR #101).
- `POST /query` `200` response now requires both `areaLimit` and `imeiBind` objects; `imeiBind` contains only `bindStatus` (PR #77).
- `401`, `403`, `404` and `422` responses now reference the Commonalities r4.4 common responses (`Unauthenticated401`, `PermissionDenied403`, `DeviceNotFound404`, `DeviceIdentifier422`); `404` returns `IDENTIFIER_NOT_FOUND` (PR #83).
- API description: "IMEI or area" clarified to "IMEI and/or area", with an explanation that a SIM card can be bound to an IMEI, an area, or both (PR #77).

### Fixed

- Removed an invalid `400 INVALID_ARGUMENT` example ("Inconsistent Device Properties") that violated Design Guide section 3.2.2 (an error must not be returned when supplied device identifiers do not match) (PR #77).
- Test definitions: corrected response schema names (`BindDeviceImeiResponse`, `UnBindDeviceImeiResponse`) and aligned asserted error codes with the definitions (`409 INCOMPATIBLE_STATE` instead of the undefined `422 UNNECESSARY_UNBIND_IMEI`) (#97, PR #88).

### Removed

- `bindImei` property from the `imeiBind` object in `POST /query` responses; only `bindStatus` is returned (PR #77).
- Local `Bind422`, `Unbind422` and `Query422` response definitions, replaced by the common `DeviceIdentifier422` (PR #83).

## iot-sim-fraud-prevention-subscriptions 0.2.0

**iot-sim-fraud-prevention-subscriptions 0.2.0 is an initial public version of this API.**

Changes documented below are compared to version 0.1.0.

- API definition **with inline documentation**:
  - [View it on ReDoc](https://redocly.github.io/redoc/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.2/code/API_definitions/iot-sim-fraud-prevention-subscriptions.yaml&nocors)
  - [View it on Swagger Editor](https://camaraproject.github.io/swagger-ui/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.2/code/API_definitions/iot-sim-fraud-prevention-subscriptions.yaml)
  - OpenAPI [YAML spec file](https://github.com/camaraproject/IoTSIMFraudPrevention/blob/r2.2/code/API_definitions/iot-sim-fraud-prevention-subscriptions.yaml)

### Breaking changes

- `securitySchemes.openId` is now an `openIdConnect` scheme referencing `CAMARA_common.yaml`, instead of an `oauth2` client-credentials flow with a hard-coded token endpoint (#96, PR #101).
- Creation scope now includes the event type, as required by the Event Subscription and Notification Guide section 4.1: `iot-sim-fraud-prevention-subscriptions:org.camaraproject.iot-sim-fraud-prevention-subscriptions.v0.imei-change:create` and `...v0.area-change:create`. The former `iot-sim-fraud-prevention-subscriptions:subscribe` scope is removed (#80, PR #102).
- Notification event types are `org.camaraproject.iot-sim-fraud-prevention-subscriptions.v0.imei-change` and `...v0.area-change`; the main API namespace is no longer used (PR #79, #97, PR #102).
- Notification event data for both event types is now a bind-breach indicator (`subscriptionId` and `bindBreach`), with `device` present only when it was supplied in the request (data minimisation, Event Guide section 2.2.2). The former `ImeiChangeEventData` / `AreaChangeEventData` payloads are removed (PR #77, PR #82, #97, PR #102).
- `sinkCredential` no longer accepts `PLAIN`; only `ACCESSTOKEN` and `PRIVATE_KEY_JWT` are allowed (Event Guide section 2.2.3, #80, PR #102).
- Only `HTTP` is allowed as notification protocol; `MQTT3`, `MQTT5`, `AMQP`, `NATS` and `KAFKA` and their settings schemas are removed (PR #84, #80, PR #102).
- `GET /subscriptions` now returns a `SubscriptionList` object with a `pagination` property instead of a plain array, and supports the `page` / `perPage` query parameters (#80, PR #102).
- `POST /subscriptions` `202` response returns `SubscriptionAsync` (`id`) instead of `subscriptionId` (#80, PR #102).
- `GET` and `DELETE /subscriptions/{subscriptionId}` now return `404 NOT_FOUND` for an unknown subscription, instead of `404 IDENTIFIER_NOT_FOUND` (#80, PR #102).
- `config.subscriptionDetail.device` is no longer required: it MUST be provided with a two-legged access token and MUST NOT be returned with a three-legged access token (#80, PR #102).

### Added

- `409` response on `POST /subscriptions` (`CreateSubscriptionConflict409`), returned when a conflicting subscription already exists (#80, PR #102).
- `SubscriptionList` schema with a `pagination` property (#80, PR #102).
- `page` and `perPage` query parameters, plus `X-Total-Count`, `X-Total-Pages` and `Link` response headers on `GET /subscriptions` (#80, PR #102).

### Changed

- `securitySchemes.openId` changed from `oauth2` client credentials with a fixed token endpoint to `openIdConnect` referencing `CAMARA_common.yaml` (#96, PR #101).
- Creation scope now includes the event type; the `...:subscribe` scope is removed (#80, PR #102).
- Notification event data replaced by the bind-breach indicator (`subscriptionId`, `bindBreach`, optional `device`) (PR #77, PR #82, #97, PR #102).
- `sinkCredential` restricted to `ACCESSTOKEN` and `PRIVATE_KEY_JWT`; the `PLAIN` credential type is no longer accepted (#80, PR #102).
- Notification protocol list reduced to `HTTP` only, in line with Commonalities r4.4 (PR #84).
- `GET /subscriptions` response changed to `SubscriptionList` with pagination; `POST /subscriptions` `202` response changed to `SubscriptionAsync` (`id`) (#80, PR #102).
- `Config` now extends `ConfigBase` from `CAMARA_event_common.yaml` and adds `subscriptionDetail` and `initialEvent`; `device` is optional (#80, PR #102).
- Subscription lifecycle event payloads and reasons (`SubscriptionStarted`, `SubscriptionUpdated`, `SubscriptionEnded`, `InitiationReason`, `UpdateReason`, `TerminationReason`), `SinkCredential`, `AccessTokenCredential` / `PrivateKeyJWTCredential`, `Protocol`, `HTTPSettings`, `ApiEventType` and `SubscriptionId` are now referenced from the Commonalities r4.4 common files instead of being defined locally (#80, PR #102).
- `404`, `400`, `403`, `422` and `429` responses now reference the Commonalities r4.4 common responses (`NotFound404`, `SubscriptionIdRequired400`, `SubscriptionPermissionDenied403`, `CreateSubscriptionDevice422`, `TooManyRequests429`) (#80, PR #102).

### Fixed

- `Subscription.types` example corrected from `org.camaraproject.iot-sim-fraud-prevention.v0.imei-change` to `org.camaraproject.iot-sim-fraud-prevention-subscriptions.v0.imei-change`, matching the `ApiEventType` definition (PR #79).
- Test definitions aligned with the API definitions (#97, PR #102): event type namespace corrected in subscribe, callback and notification features; `SubscriptionAsync` and `$.id` used for the `202` response; callback assertions aligned with `BindBreachEventData`; `401` asserts `UNAUTHENTICATED` and `409` asserts `INCOMPATIBLE_STATE`; the invalid `422 IDENTIFIER_MISMATCH` scenario removed (Design Guide section 3.2.2 forbids returning an error when supplied device identifiers do not match).

### Removed

- Local schemas duplicating Commonalities r4.4 definitions: `PlainCredential`, `AccessTokenCredential`, `PrivateKeyJWTCredential`, `Protocol`, `SinkCredential`, `HTTPSettings`, `SubscriptionId`, the lifecycle payload schemas and their reason enums (#80, PR #102).
- `SubscribeFraudPreventionResponseAsync`, replaced by `SubscriptionAsync` (#80, PR #102).
- Local response definitions `SubscribeBadRequest400`, `CallbackBadRequest400`, `Callback410` and `QuotaOrRateLimit429`, replaced by the common definitions (#80, PR #102).
- `ImeiChangeEventData` and `AreaChangeEventData` schemas, together with the `Area`, `AreaType`, `Circle`, `Point`, `Latitude` and `Longitude` schemas they referenced (PR #77).
- Notification protocols `MQTT3`, `MQTT5`, `AMQP`, `NATS` and `KAFKA`, together with their local request/response and settings schemas (PR #84).
