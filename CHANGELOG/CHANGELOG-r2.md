## iot-sim-fraud-prevention 0.2.0-rc.1

**iot-sim-fraud-prevention 0.2.0-rc.1 is a release-candidate version of this API.**

Changes documented below are compared to version 0.1.0.

- API definition **with inline documentation**:
  - [View it on ReDoc](https://redocly.github.io/redoc/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.1/code/API_definitions/iot-sim-fraud-prevention.yaml&nocors)
  - [View it on Swagger Editor](https://camaraproject.github.io/swagger-ui/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.1/code/API_definitions/iot-sim-fraud-prevention.yaml)
  - OpenAPI [YAML spec file](https://github.com/camaraproject/IoTSIMFraudPrevention/blob/r2.1/code/API_definitions/iot-sim-fraud-prevention.yaml)

### Breaking changes

* N/A

### Added

* `POST /query` response now includes the `device` object, so the API consumer can
  disambiguate which device identifier was matched
* `422 SERVICE_NOT_APPLICABLE` response, linking to the common `DeviceIdentifier422`
  error definition, for identified devices to which this service does not apply

### Changed

* `POST /query` `200` response now requires both `areaLimit` and `imeiBind` objects;
  `imeiBind` contains only `bindStatus`
* API description: "IMEI or area" clarified to "IMEI and/or area", with an added
  explanation that a SIM card can be bound to an IMEI, an area, or both

### Fixed

* Error responses now use the Commonalities r4.4 common definitions
  (`DeviceIdentifier422`, `IdentifierNotFound404`, `Generic409`) instead of
  locally defined variants
* Removed an invalid `400 INVALID_ARGUMENT` example that violated Design Guide
  section 3.2.2 (an error must not be returned when supplied device identifiers
  do not match)

### Removed

* `bindImei` property from the `imeiBind` object in `POST /query` responses

## iot-sim-fraud-prevention-subscriptions 0.2.0-rc.1

**iot-sim-fraud-prevention-subscriptions 0.2.0-rc.1 is a release-candidate version of this API.**

Changes documented below are compared to version 0.1.0.

- API definition **with inline documentation**:
  - [View it on ReDoc](https://redocly.github.io/redoc/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.1/code/API_definitions/iot-sim-fraud-prevention-subscriptions.yaml&nocors)
  - [View it on Swagger Editor](https://camaraproject.github.io/swagger-ui/?url=https://raw.githubusercontent.com/camaraproject/IoTSIMFraudPrevention/r2.1/code/API_definitions/iot-sim-fraud-prevention-subscriptions.yaml)
  - OpenAPI [YAML spec file](https://github.com/camaraproject/IoTSIMFraudPrevention/blob/r2.1/code/API_definitions/iot-sim-fraud-prevention-subscriptions.yaml)

### Breaking changes

* N/A

### Added

* N/A

### Changed

* Notification event data for both event types now uses a boolean state indicator
  (`bindBreach`), replacing the previous IMEI and area payloads
* Notification protocol list reduced to `HTTP` only, in line with Commonalities
  r4.4 (the other protocols remain commented out for future use)

### Fixed

* Corrected the event type namespace in the `Subscription.types` example

### Removed

* Notification protocols `MQTT3`, `MQTT5`, `AMQP`, `NATS` and `KAFKA`, together
  with their local request/response and settings schemas
